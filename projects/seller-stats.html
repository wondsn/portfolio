판매자센터 통계 서비스 런칭 및 고도화

판매 데이터를 활용해 판매자가 스스로 판매 촉진 기회를 분석하고 실행할 수 있도록 만든 판매자센터(ESM+) 통계 서비스입니다. 데이터 집계 파이프라인부터 조회 API, 대용량 엑셀 다운로드, 화면까지 새로 구축했습니다.

01 프로젝트 개요

S

Situation · 상황

판매자가 자신의 판매·유입 데이터를 직접 분석해 판매 촉진 기회를 찾고 실행할 수 있도록, 판매자센터(ESM+)에 통계 서비스를 새로 만드는 프로젝트였습니다.

T

Task · 과제

파트 리드로 BE·FE·데이터 엔지니어로 구성된 팀을 이끌며 다음을 맡았습니다.

  • 판매·유입 데이터 집계 및 데이터 서빙
  • 대용량 엑셀 다운로드 아키텍처 설계
  • 요약·리뷰 현황·인기 카테고리 화면 개발
A

Action · 행동

  • Databricks(Spark)로 판매·유입 데이터를 집계하는 파이프라인 구축
  • 조회 패턴에 맞춰 일·주·월 트렌드는 Elasticsearch, 시간 단위·오늘 통계는 RDB로 저장소 분리
  • 대용량 엑셀은 exceljs 스트리밍 기반 Node.js 파일 서버로 분리
  • Next.js·React로 요약, 리뷰 현황, 인기 카테고리 화면 개발
R

Result · 결과

  • 하루 3억 건의 데이터를 2시간 안에 집계
  • 통계 조회 p95 20ms
  • 최대 100만 행 엑셀 다운로드를 타임아웃 없이 제공
  • 월 이용 판매자 1.22만 명, 월 PV 30만 건

03 핵심 기술 및 기술 의사결정

  • 저장소 분리: RDB + Elasticsearch

    인프라 운영 비용을 고려해 별도 저장소를 새로 도입하지 않고, 이미 운영 중인 Elasticsearch 클러스터를 활용했습니다. 일·주·월 트렌드, 키워드, TOP 50처럼 기간·카테고리별 집계와 검색이 많은 조회는 Elasticsearch에 잘 맞는 패턴이었습니다. 반대로 Elasticsearch는 문서를 자주 부분 수정하면 재색인 비용이 커서, 준실시간으로 갱신되는 시간 단위·오늘 통계는 RDB로 분리해 약점을 보완했습니다.

  • 엑셀 다운로드: Node.js + exceljs 스트리밍 파일 서버

    최대 100만 행의 엑셀을 서버 메모리에 한꺼번에 올리지 않고, 행 단위로 생성해 바로 응답으로 흘려보내도록 exceljs의 스트리밍 writer를 사용했습니다(네이버 D2 사례 참고). 무거운 다운로드 트래픽이 통계 API에 영향을 주지 않도록 별도 Node.js 파일 서버로 분리했습니다.

  • 집계 플랫폼: Databricks

    Spark로 대량 집계 시간을 줄일 수 있고, Job 스케줄링·모니터링 같은 운영 기능이 내장돼 있으며, 클러스터를 직접 운영하지 않는 관리형 레이크하우스 플랫폼이라 인프라 부담이 적어 Databricks를 사용했습니다.

04 아키텍처

Kafka로 들어오는 앱·웹 페이지뷰 로그와 원천 DB 데이터를 Databricks에서 집계합니다. 일·주·월 트렌드와 키워드·TOP 50 데이터는 Elasticsearch에, 시간 단위 통계는 통계 DB에 적재하고, 오늘 데이터는 원천 DB에서 통계 DB로 실시간 동기화합니다. 통계 BE가 두 저장소를 조회해 통계 FE와 ESM+ 다른 도메인에 API로 제공합니다.
